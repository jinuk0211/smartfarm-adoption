# 대회 명세서는 코드의 어디에 쓰였나요?

**명세서의 컬럼·타입·키를 코드에 반영했고, 시설과 경영조사를 연결하는 모델 경로를 구현했습니다. 실제 미개방 농가자료로 학습했다는 뜻은 아닙니다.** 현재 로컬의 대회 자료는 명세 TXT·ZIP이며, 실행 확인은 합성 40시설·80작기로 했습니다. 별도로 확보한 공개 농가자료의 실험 성능과 구분합니다.

![명세서 항목이 연결·학습·계산 코드로 이어지는 흐름](../assets/diagrams/dsz-spec-usage-easy.png)

[큰 글씨 세로판](../assets/diagrams/dsz-spec-usage-portrait.png)도 제공합니다. 위 그림은 구현 흐름 요약입니다. 경영조사 집계기간·합산 방식은 원자료와 함께 현장에서 확인해야 합니다.

## 1. 11종 중 현재 구현에 반영한 범위

| 자료 | 현재 사용 위치 | 현재 학습 입력 여부 |
| --- | --- | --- |
| DZ_002 시설 | 작기 정의, 계획 변수 7개 구성, 시설별 평가 그룹 | 7개 계획 변수로 사용 |
| DZ_004 경영조사 | 시설·작기 연결 후 출하량·총수입 목표 후보 구성 | 입력이 아닌 학습 목표 |
| DZ_001 환경 · DZ_003 생육 | 제공된 파일의 컬럼·타입·키 검사 | 사용하지 않음 |
| DZ_005 기상 · DZ_006 기상특보 · DZ_007 태풍 | 제공된 파일의 컬럼·타입·키 검사 | 사용하지 않음 |
| DZ_008 토마토 이미지 · DZ_009 종묘장 주문 | 현재 DSZ 모델 범위에서 제외 | 사용하지 않음 |
| DZ_010 소도체 · DZ_011 돼지도체 경락가격 | 시설작물 도입 판단 범위에서 제외 | 사용하지 않음 |

스키마로 옮긴 **7종의 79필드**는 환경 16 + 시설 12 + 생육 16 + 경영조사 7 + 기상 10 + 특보 8 + 태풍 10개입니다. **79개를 전부 예측 변수로 넣은 것은 아닙니다.**

## 2. 시설 명세 → 계획 입력 7개

| 원 명세 컬럼 | 코드 변수 | 의미 |
| --- | --- | --- |
| ITEM_NM | crop | 품목 |
| AREA_NM | region | 지역 |
| SACT_INTLCK_SPR_NM | greenhouse_type | 단동·연동 구분 |
| HTHS_SCL_CN | greenhouse_size | 온실 규모 설명 |
| HTHS_SFC | area_m2 | 온실 면적 |
| FRMTM_BGNG_YMD의 연도 | planned_start_year | 시작 연도 |
| FRMTM_BGNG_YMD의 월 | planned_start_month | 시작 월 |

[실제 변환 코드](../src/dsz_data.py#L258) · [모델 입력 목록](../src/dsz_model.py#L12)

시설ID는 연결과 시설별 평가 그룹 구분에 씁니다. 실제 작기 종료일, 이후 환경·생육 관측값은 도입 전 예측의 입력에서 제외합니다. 작기 종료일은 학습자료를 연결할 때만 쓰며, 사용자가 미리 알아야 할 입력이 아닙니다.

## 3. 경영조사 → 학습 목표 2개

| 원 명세 컬럼 | 코드 변수 | 단위 |
| --- | --- | --- |
| ALL_SHPMNT_KGUNT_QTY | reported_shipment_kg | kg |
| ALL_INCM_AMT | reported_revenue_krw | 원 |

두 목표는 자료가 유효한 행을 각각 골라 별도로 학습합니다. **총수입은 비용을 빼기 전 매출이며 순이익이 아닙니다.**

연결 조건은 같은 시설ID이고, 경영조사 조사일이 시설의 작기 시작일~종료일 안에 포함되며, 해당하는 작기가 정확히 하나인 경우입니다. 기간은 양 끝을 포함합니다. 모호한 작기, 중복, 잘못된 날짜, 결측·음수 목표 등은 사유와 함께 기록합니다. [연결 코드](../src/dsz_data.py#L179)

**명세만으로 경영조사가 증분인지 누계인지, 완결된 작기 총량인지 확정할 수 없습니다.** 현재 코드는 단일 기록(기본값)·증분 합산·최신 누계 중 선택한 정책을 결과에 명시하며, target_period_confirmed=false를 남깁니다. 실제 원자료 사용 전 집계기간과 합산 방식을 확인해야 합니다. [현장 안내](dsz_onsite_guide.md) · [학습 방법](dsz_model_method.md)

## 4. 다른 5종은 무엇을 검사하나요?

파일이 제공된 경우 정의 컬럼 전체의 존재, 숫자의 정밀도·소수자리·유한성, 문자열 길이, 날짜 형식·유효성, 기본키 공란과 복합키 중복을 검사합니다. 추가 컬럼은 기록하며 비키 컬럼의 공란은 허용합니다.

이는 **센서값의 현실적 범위, 실제 측정 단위, 시설 테이블과의 외래키 연결, 시간 간격의 정합성까지 검증했다는 뜻은 아닙니다.** 5종 60필드는 현재 모델 입력 대신 검사 목록으로 기록합니다. [파일 읽기](../src/dsz_data.py#L91) · [타입 검사](../src/dsz_data.py#L57) · [행·키 검사](../src/dsz_data.py#L128) · [준비 결과](../src/dsz_data.py#L281)

## 5. 예측값은 어디로 가나요?

- 출하량 경로: 예측 kg × 별도로 선택한 농가 수취단가 → 매출.
- 총수입 경로: 예측한 원 금액을 매출로 직접 사용.
- 두 경로 중 하나를 선택하고 비용 가정과 비교해 소득·현금흐름·회수기간을 계산합니다. 두 경로를 더하거나, 총수입에 면적·단가를 다시 곱하지 않습니다.
- 작기 예측을 연간 계산에 사용할 때는 연 1작기 가정을 확인하며 합성·현장 미검증 표식을 유지합니다.

| 구분 | 상태 |

| 실제 현장 확인 | 값의 분포·결측·키 연결률·목표 집계기간과 새 농가·미래 시점 성능 확인 필요 |

## 7. 대회의 실제 데이터 활용 실적과 구분

2026년 공식 통합공고는 예선 기술평가에서 방문일수와 미개방데이터 연계·활용 여부를 평가하고, 최소기준 불충족 시 본선에 진출할 수 없다고 안내합니다. 본선에서도 미개방데이터의 활용 기여도와 자료 간 연계 완성도를 평가합니다. [과학기술정보통신부 통합공고 제2026-0918호, 5–6쪽](https://www.kbiz.or.kr/download.do?fleDwnDs=bbsAttachFile&orgalFle=323032365feb8db0ec9db4ed84b05f41495fed9881ec8ba05fecb18ceba6b0eca7805fed86b5ed95a9eab3b5eab3a0ebacb82e706466&saveFle=178832391058349571.pdf&seq=92571).

따라서 **이 저장소의 명세 반영·합성자료 실행만으로 실제 미개방데이터 활용 실적이나 대회 최소기준 충족을 입증한 것은 아닙니다.** 현재 코드는 현장에서 실제 파일을 분석하기 위한 준비물이며, 원자료 분석 결과와 허용된 범위의 산출물을 별도로 확보해야 합니다. 참가자의 방문·현장 분석 이력과 세부 최소기준은 별도 확인 사항이며, 이 문서가 개별 참가 적격 여부를 판정하지 않습니다.
