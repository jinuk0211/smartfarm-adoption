# 명세서 데이터의 작기·집계기간 연결 보완

2026-10-18. **조사일과 집계기간을 혼동한 기존 오류를 수정했습니다.** 실제 DSZ 미개방 원자료는 로컬 0행이며 새 실제 모델을 학습하지 않았습니다.

기존에는 시설ID가 같고 조사일이 작기 안에 있으면 기간 미확정 후보도 학습할 수 있었습니다. 증분 정책을 잘못 고르면 100kg·200kg 누계를 300kg으로 더할 수 있었고 연 1작기 동의만으로 경제성에 진입할 수도 있었습니다.

## 현재 규칙

- 근거 없는 기록은 감사 후보로만 보존하고 학습·예측·경제성 연결을 차단합니다.
- 실제 정의 문서·원본 파일 해시, 집계 정책, 검토 기록을 대조합니다.
- 원본 조사행→시설·작기 매핑과 **행별 집계 시작·끝**을 확인합니다.
- 단일 총량은 전체 작기 일치, 증분은 겹침·공백 없는 전체 작기 포함, 누계는 작기 시작부터 작기말 최종 누계를 요구합니다.
- 작기 종료 뒤 조사한 정산도 확인된 매핑으로 올바른 작기에 연결합니다.
- 일부만 확인됐다면 감사 원본은 보존하고 확인된 적격 행만 학습합니다.
- 사용·제외 내역, 정책·근거·선택 해시를 학습·예측·경제성에 전달합니다.

정책 선택·플래그 변경·연 1작기 동의만으로 우회할 수 없습니다. 식별자와 선행 0을 보존하며 결측을 0으로 채우지 않습니다. 확인 JSON의 정확한 필드는 [입력 계약](dsz_schema_contract.md), 실행법은 [현장 안내](dsz_onsite_guide.md)에 있습니다. 원문 명세서 자체에는 집계기간 정의가 없어 그 해시만으로 확인 완료를 선언할 수 없습니다.

사전 입력은 품목·지역·단동/연동·온실 규모 설명·면적·시작 연도·월의 **7개**입니다. 환경·생육·기상·특보·태풍은 컬럼·타입·키 검사와 목록 작성만 하며 모델 입력·비용으로 쓰지 않습니다. [현재 데이터 흐름](../DATA_FLOW.md)과 [명세 반영 설명](dsz_spec_usage.md)이 이전 이미지·PPT의 연결 설명을 대체합니다.

## 로컬 소프트웨어 검사 기록

수정 당시 로컬 대상 검사 **107개 + 하위 검사 15개 통과**, 관련 Python 11개 파일 Ruff와 PowerShell 문법 검사를 통과했습니다. 합성 모델의 예측→근거 기록→경제성 연결도 확인했습니다.

약 **245MB 오프라인 ZIP은 로컬 산출물이며 공개 다운로드가 아닙니다.** 50개 매니페스트 항목과 SHA256을 대조하고 묶음 안의 코드로 근거 없는 합성 80행 차단·가상 근거 동반 80행 전달을 확인했습니다. 새 가상환경의 의존 패키지 재설치 검사는 아닙니다. 현재 공개 소스 검사는 [README](../README.md#검증과-공개-범위)에 별도로 기록합니다.

준비 단계는 원본·정의 파일의 실제 해시를, 이후 단계는 신뢰하는 로컬 준비 산출물·선택 내역의 일관성을 검사합니다. **문서의 의미·진위나 수치 정확성을 기관 대신 인증하는 기능이 아닙니다.** 실제 자료의 기간·판매·전체 비용·투자 근거와 실제 결과 비교가 더 필요합니다.

외부 연락·메일·신청·운영 웹사이트 재배포는 하지 않았습니다. 센터 승인이나 실제 농가 경제성 검증 완료를 주장하지 않습니다.
